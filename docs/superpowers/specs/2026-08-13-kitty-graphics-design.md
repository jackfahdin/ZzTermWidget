# Kitty 图形协议（核心子集）设计规格

日期：2026-08-13
状态：已批准（头脑风暴结论；规格自检已对照上游协议原文修正）
上游参考：Kitty terminal graphics protocol（https://sw.kovidgoyal.net/kitty/graphics-protocol/）

## 1. 背景与目标

ZzQTermWidget 第五轮已实现 Sixel 图形协议，建立了"屏级图像表 + 行级引用 + 生命周期挂钩 + 文本下层叠加绘制"的完整锚定设施。Kitty 图形协议是新一代终端图像事实标准（yazi、lf、ranger、neofetch、matplotlib kitty 后端等），与 Sixel 互补。本轮以**核心子集**接入 Kitty 协议，复用并抽象现有图形锚定层，避免两套生命周期逻辑并存。

对标差距清单中本项完成后，图形协议维度（Sixel + Kitty）即告齐整。

### 范围（核心子集，明确约定）

包含：

- APC 转义通道解析：`ESC _ G key=value,… ; base64负载 ESC \`，分块重组（`m=1` 续块 / `m=0` 末块）。
- 动作：`a=t`（仅传输）、`a=T`（传输并显示）、`a=p`（放置已传输图像）、`a=d`（删除）、`a=q`（查询：试加载并应答，不存储不替换）。
- 像素格式：`f=100`（PNG，`QImage::fromData` 解码）、`f=32`（RGBA，缺省）、`f=24`（RGB）。
- 压缩：`o=z`（RFC 1950 zlib 流，先于 base64 编码压缩）。
- 图像标识：`i=` 图像 id（1..4294967295）、`p=` 放置 id；同一图像可多次放置，同 `(i, p)` 重复放置视为替换。
- 放置参数：源矩形 `x/y/w/h`（像素，缺省整图）、单元格内像素偏移 `X/Y`（必须小于单元格尺寸）、显示区 `c×r`（单元格数，只给一个时另一个按宽高比推算）、`z=` z-index、光标策略 `C=1`。
- 删除变体：`d=a` 删除全部可见放置；`d=i` 按图像 id（同时给 `p=` 时只删该放置）；`d=c` 删除与光标单元格相交的放置。小写仅删放置，大写（`A/I/C`）连同释放无其他引用的图像数据。
- 命令应答：成功回 `ESC _ G i=<id>[,p=<pid>];OK ESC \`，失败回 `ESC _ G i=<id>;<错误码>:<说明> ESC \`（如 ENOENT/EINVAL）；`q=1` 抑制成功应答、`q=2` 抑制失败应答（上游原文定义）。
- 重传语义：以已有 `i=` 重传图像数据时，先删除旧图像及其全部放置，新数据落库但不自动显示（上游原文要求，防止无关程序复用 id 出现分歧行为）。

明确不做（YAGNI，未知键一律静默忽略；不支持的介质/动作回错误码）：

- 文件/临时文件/共享内存传输（`t=f/t/s`）：回 `EINVAL` 类错误码。
- 动画（`a=f/a/c`）、帧合成：回错误码。
- Unicode 占位符（`U=`）、相对放置（`P/Q/H/V`）、图像编号（`I=`）：忽略（`I=` 视为未知键；因不支持，不会产生"同时给 i 和 I"的 EINVAL 分支）。
- 其余删除变体（`d=n/f/q/r/x/y/z`）：忽略。
- 图像与鼠标交互命中。

## 2. 架构

方案 A（已与用户确认）：**统一图形锚定层**。将第五轮 Sixel 的存储/引用/绘制设施抽象为协议无关层，Kitty 作为第二个协议前端接入。生命周期挂钩只维护一份，像素预算两协议共享。

```
APC 字节流 → Vt102Emulation APC 累积通道（新增，镜像 DCS 通道）
           → KittyGraphicsParser（纯逻辑：键值解析 / 分块重组 / base64 / zlib / 像素解码）
           → Screen 图形存储（重构：协议无关图像表 + 行级引用 + kitty 放置表）
           → TerminalDisplay 叠加绘制（文本下层：sixel + z<0；文本上层：z≥0，新增通道）
```

## 3. 协议解析层

### 3.1 APC 累积通道

- Kitty 图形命令走 APC（`ESC _ G … ESC \`）。现有 tokenBuffer 仅 100KB，不足以承载 base64 图像负载；参照第五轮 DCS 32MB 独立通道模式，新增 APC 累积通道，与 `_sixelData` 同级管理。
- 编码后累积上限 **350MB**（约对应 256MB 解码像素预算），超限丢弃整条命令并复位通道。
- ST（`ESC \`）结束累积并触发解析；CAN/SUB 中止路径与 DCS 通道一致。
- 分块规则（上游原文）：每块 base64 ≤ 4096 字节，除末块外长度须为 4 的倍数；解析器对违规块宽容处理但不主动依赖。客户端必须发完一张图的全部分块才能发下一条图形命令；分块流被新命令打断时丢弃半成品。
- **显示用的光标位置以收到末块时的光标位置为准**；整条序列收齐并校验通过前不产生任何显示。

### 3.2 KittyGraphicsParser（纯逻辑，可独立单测）

- 键值段解析：逗号分隔的 `key=value`；未知键静默忽略（协议要求）；首块携带全部控制键，续块仅允许 `m`（及可选 `q`）与负载。
- 分块重组：`m=1` 累积，`m=0`（缺省）收尾；负载段 base64 解码（忽略空白）。
- `o=z`：zlib 原始流解压。实现采用"4 字节大端长度前缀 + `qUncompress`"技巧，不引入新依赖。预期解码长度：`f=24/32` 为 `s×v×每像素字节数`；`f=100` 取 `S` 键（上游规定 PNG 与压缩并用时客户端必须提供 `S`），缺失则回 `EINVAL`。
- 像素解码：
  - `f=100`：负载整体为 PNG 文件字节，`QImage::fromData` 解码，统一转 `Format_ARGB32`。
  - `f=32` / `f=24`：按 `s`（宽）、`v`（高）逐像素组装 RGBA/RGB，转 ARGB32；sRGB 色彩空间原样接受。
- 解码前预检：`s×v×4` 计入共享像素预算，超限直接失败（回错误码，不落库）。

### 3.3 限制

- 单图尺寸硬上限 10000×10000。
- 与 Sixel 共享 256MB 像素预算（现存两协议图像总字节数，ARGB32 4 字节/像素）；预算紧张时优先淘汰无放置引用的图像（上游建议行为）。
- 畸形命令：能定位 `i=` 时回错误码，否则静默忽略；绝不中断主转义解析状态机。

## 4. 统一图形锚定层（Screen 重构）

### 4.1 重构内容

- 将 `Screen` 内 sixel 专属结构（`SixelImage`、`ImageRefLine`、`_imageLines`、`_sixelImages`、预算记账）泛化为协议无关命名（如 `ScreenImage` / `_images`），行为不变；sixel 前端改用泛化结构。
- 六个生命周期挂钩点（addHistLine / moveImage / clearImage / resizeImage / setScroll / reset）维持单一实现，两协议共享。

### 4.2 Kitty 放置语义

- `KittyImage`：图像 id → 像素数据（存入泛化屏级表，与 sixel 同预算）。`i=0`（缺省）表示匿名图像：可显示但不占用 id 命名空间，多个匿名图像/放置允许并存。
- `KittyPlacement`：`{ imageId, placementId, anchorLine, col, cols, rows, srcX, srcY, srcW, srcH, cellXOff, cellYOff, zIndex }`。
  - `anchorLine` 使用 history+screen 统一非负行坐标系（与 OSC 8 / Sixel 一致）。
  - 行级引用挂在放置覆盖的每一行上，滚动/清行/resize/复位由共享挂钩管理；图像随文本滚动（kitty 语义：放置在单元格上的图像跟随内容）。
  - `p=0`/缺省且 `i≠0` 时，多次 `a=p` 产生多个放置；同 `(i, p≠0)` 重复放置视为替换（可无闪烁移动/缩放）。
- 光标语义（上游原文，**与 sixel 的 xterm 语义不同，注意区分实现路径**）：放置后光标右移放置矩形列数、下移放置矩形行数；若因此越出屏幕或滚动区，落点由实现自定；`C=1` 时光标不移动。
- 删除（`a=d`）：
  - `d=a`：删除全部可见放置（大写 `A` 同时释放无引用图像数据）。
  - `d=i` + `i=`：删除该图像全部放置；同时给 `p=` 时只删该 `(i, p)` 放置（大写 `I` 同时释放无引用图像数据）。
  - `d=c`：删除与光标单元格相交的放置（大写 `C` 同时释放无引用图像数据）。
  - 图像数据释放条件：无任何存活放置引用（含回看历史中的引用）。
  - 分块上传未完成时收到删除命令：中止半成品上传。
- z-index 排序：同 z 重叠时 id 小者视为更低层；同 z 同 id 行为未定义（按插入序）。`z<0` 画在文本之下；`z≥0` 画在文本之上。上游"低于 INT32_MIN/2 时沉入非默认背景色单元格之下"的细分档本轮不做（记录为遗留）。

### 4.3 接口边界

- `lib/include/qtermwidget.h` 公共头不动；新增结构位于内部头。
- `Screen` 暴露 kitty 前端所需的最小内部接口（放置/删除/查询/按行取放置切片），风格对齐现有 `sixelImage()` / `hasImages()`。
- 命令应答经 `Emulation` 回写通道（复用 DECRQM/查询应答既有 sendText 路径）；`a=q` 查询须立即应答，不等后续输入处理。

## 5. 绘制层（TerminalDisplay）

- 现有 `drawSixelImages()`（文本层之下）泛化：绘制 sixel 放置 + `z<0` 的 kitty 放置。
- 新增文本上层通道：文本绘制之后、光标绘制之前（图像在文本之上、光标之下），绘制 `z≥0` 的 kitty 放置；半透明图像按 z 序 alpha 混合。
- 目标矩形：`(col, anchorRow)` 单元格起，加 `X/Y` 像素偏移，尺寸 `c×r` 单元格；源矩形 `x/y/w/h` 与源图取交；缺省 `c/r` 时按源矩形原始尺寸换算单元格数（向上取整），只给一个时另一个按宽高比推算；超右缘截断。
- 脏区：复用 `_graphicsDirty` 图形脏标志机制；回看历史两视图并集置脏逻辑（第五轮 F1 修复）对 kitty 放置同样生效（含图行按锚定行级引用判定）。

## 6. 错误处理

| 情形 | 行为 |
|------|------|
| 未知键 | 静默忽略（协议要求） |
| 不支持的传输介质 `t=f/t/s`、动画动作 | 回 `EINVAL` 类错误码（有 `i=` 时），不崩 |
| `a=p` 引用不存在的图像 id | 回 `ENOENT` |
| 像素预算超限 / 尺寸超限 | 回错误码，命令整体丢弃 |
| base64/zlib/PNG 解码失败、PNG+o=z 缺 `S` | 回错误码，不产生放置 |
| 分块流被新命令打断 | 丢弃半成品，按新命令处理 |
| 删除命令到达时分块上传未完成 | 中止半成品上传 |
| 累积超 350MB | 丢弃整条命令，通道复位 |

## 7. 测试（新套件 tst_kittygraphics，Qt Test）

镜像 tst_sixel / tst_rendering 既有设施：

1. 解析器单测：键值解析、未知键容忍、分块重组（含打断与 4096/4 倍数规则）、`o=z` 解压、畸形输入容错。
2. 像素格式：1×1 与多像素 RGB/RGBA 组装正确性；最小 PNG 往返。
3. 放置生命周期：锚定、随滚动迁移、清行/清屏/resize/复位后的存活与回收（对齐 tst_sixel 对应用例）；光标默认移动与 `C=1` 不移动。
4. 删除变体：`d=a/i/i+p/c` 及大写释放语义、无引用图像回收、半成品上传中止。
5. 应答：成功 OK（含 `p=` 回显）、ENOENT/EINVAL 错误码、`q=1` 抑制成功、`q=2` 抑制失败；`a=q` 不存储不替换。
6. 重传语义：同 id 重传后旧放置消失、新数据需重新放置才显示。
7. z-index 离屏渲染：`QWidget::render(&QImage)` 逐像素断言 z<0 在文本下、z≥0 在文本上、同 z 按 id 排序（先 warmup 吃掉 `_drawTextTestFlag`）。
8. 预算强制：超 256MB 拒绝且既有图像不受影响；优先淘汰无放置引用图像。

测试注意事项（沿用既有事实）：`emu.setKeyBindings(QString())`；`tests/CMakeLists.txt` 的 `QTERMWIDGET_TESTS` 列表追加 `kittygraphics`。

## 9. 已知遗留（有意留待）

- 非等宽字体下图像 x 坐标与文本不对齐（终端惯例等宽，与 sixel 轮一致）。
- 动画、Unicode 占位符、相对放置、图像编号 `I=`、t=f/t/s 传输介质、其余删除变体：待后续轮次按需求启动。
- z-index 低于 INT32_MIN/2 沉入非默认背景单元格之下的细分档未实现。
- 放置跨越 DECSTBM 滚动区边界（或被 insertLine/deleteLine 切割）时行一致性破裂：
  kitty 整图画法可能错位（sixel 逐行切片无此问题）；根治方向是 kitty 绘制改逐行水平带切片。
  （已根治：2026-08-14 正确性修复包，kitty 绘制改逐行水平带切片）
