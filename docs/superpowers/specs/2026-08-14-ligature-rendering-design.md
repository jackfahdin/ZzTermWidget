# 编程连字渲染（可选开关）设计规格

日期：2026-08-14
状态：已批准（头脑风暴结论）
参考实现：kitty / WezTerm / Windows Terminal 的编程连字行为；Qt 6 文本整形（内部走 HarfBuzz）

## 1. 背景与目标

现代编程字体（Fira Code、Cascadia Code、JetBrains Mono 等）通过 OpenType `liga`/`calt` 特性把 `->`、`=>`、`!=`、`>=` 等 ASCII 运算符序列渲染为连字字形。主流终端（kitty、WezTerm、Windows Terminal）均支持且多为默认开启。当前 ZzQTermWidget 按"同样式片段整段 drawText"绘制（轮 4 批绘制设施），Qt 的 drawText 内部虽会整形，但既无连字字形宽度校验也无脏区配套，行为不可靠。

目标：以**可选开关**（默认关，opt-in）支持编程连字——ASCII 运算符序列在字体具备恰好等宽的连字字形时整段整形绘制，否则静默回退现有逐格/整段路径。

## 2. 范围

包含：

- `TerminalDisplay` 新增公共开关 `setLigaturesEnabled(bool)` / `ligaturesEnabled()`，默认 false。
- 连字判定设施：片段内可连字子区间探测 + 整形宽度校验（`QFontMetricsF::horizontalAdvance(子串) == 格数 × _fontWidth`）。
- 绘制：校验通过的子区间一次 drawText 整段绘制（Qt 整形自动产出连字字形）；不通过回退现有路径。
- 跨度脏区配套：连字序列任一格变脏时脏跨度扩展到整个序列。
- 测试：离屏像素双路径、静默回退、脏区扩展、样式边界。

明确不做（YAGNI）：

- 拉丁文通用连字（fi、fl 等）——等宽字体命中率低，收益小。
- 完整 OpenType 复杂文字整形（阿拉伯文连写等）——与单元格模型根本冲突。
- vendored HarfBuzz 或任何新第三方依赖——Qt 内建整形已足够。
- 光标处拆开连字（kitty 也不拆，光标块画在连字字形之上）。
- 连字与 quardCRT #33 修复分支、bidi 分支的叠加（见 §3.4 互斥约定）。

## 3. 详细设计

### 3.1 开关与公共 API（TerminalDisplay.h/.cpp）

- 新增成员 `bool _ligaturesEnabled = false;` 与公共 setter/getter：
  - `void setLigaturesEnabled(bool enabled);`
  - `bool ligaturesEnabled() const;`
- setter 内若值变化，触发全量重绘（`update()`），不做局部刷新优化。
- 注释遵循项目约定：中文 Doxygen。

### 3.2 连字判定设施（lib/src/display/，新内部工具）

新增内部类（如 `LigatureHelper`，头+实现放 `lib/src/display/`，不进入公共头）：

- **可连字字符集**：ASCII 运算符区字符，初版集合
  `! # $ % & * + - . / : ; < = > ? @ \ ^ _ { | } ~`
  （空格、字母数字、逗号、括号、引号不参与；集合以静态查找表实现，可在后续轮次微调）。
- **探测**：输入样式均匀的 `std::u32string` 片段，输出若干"可连字子区间"（起始索引 + 长度，长度 ≥ 2 且区间内全部字符命中集合）。
- **整形校验**：对每个候选子区间，调用
  `QFontMetricsF(painter.font()).horizontalAdvance(QString::fromStdU32String(子串))`
  与 `子串格数 × _fontWidth` 比较，**相等**（整像素容差 0.5px 内）才判定可连字。Qt 整形默认启用 `liga`/`calt`，等宽编程字体的连字字形恰好占 n 格宽；字体无连字字形时整形结果就是逐字宽度之和——对非 1 格宽字形的普通运算符序列该校验恒成立，因此连字判定等价于"整形后总宽不变"，无需逐 glyph 检查。

> 注意：该校验只保证"整段绘制不破坏对齐"，连字是否真的发生由字体决定——这正是目标语义（有连字字形就连，没有就回退，调用方无感知）。

### 3.3 绘制集成（drawContents → drawTextFragment → drawCharacters）

- 改造点在 `drawCharacters()`（TerminalDisplay.cpp:930）的默认整段路径（:1068 起的 else 分支、`isLineCharString` 为假时）。
- 开关开启且片段含可连字字符时：
  1. 用 §3.2 设施把片段拆成"连字子区间 + 普通子区间"交替序列；
  2. 普通子区间按现有逻辑整段 drawText（带 `LTR_OVERRIDE_CHAR` 或 bidi 分支）；
  3. 连字子区间在其起始格 x 坐标处一次 drawText（不加 LTR 覆盖字符，保证整形上下文纯净）。
- 开关关闭时代码路径与现状**逐字节一致**（在默认分支入口加一次开关判断，零行为变化）。
- 手绘下划线（轮 8，`drawStyledUnderline` 按片段 rect 手绘）不受影响：连字不跨片段，片段 rect 不变。

### 3.4 互斥约定

- `_fix_quardCRT_issue33` 分支（:1012）优先：该开关开启时不做连字拆分（维持逐字修正绘制）。
- `_bidiEnabled` 分支（:1079）优先：bidi 开启时不做连字拆分（整形方向上下文优先）。
- 即连字只在"默认非 bidi、非 #33 修复"的整段路径生效。三个开关两两不叠加，避免逻辑纠缠。

### 3.5 跨度脏区配套（轮 7 设施）

- 连字跨格：序列中间格内容变化时，仅重绘该格会残留连字字形墨迹。
- 方案：开关开启时，`drawContents` 行内片段循环（:2419 的聚合 while 循环）探测到片段含可连字序列后，将该行脏跨度向两侧扩展到序列边界；保守实现允许直接升级为整行置脏（复用斜体"邻居整行升级"先例，轮 7 已验证成本可接受）。
- 具体落点由实现计划勘察后确定（轮 7 跨度脏区代码在 drawContents 批次路径内）。

### 3.6 性能

- 开关关闭：仅一次布尔判断，零开销（benchmark 门禁：与现状无统计学差异）。
- 开关开启：片段不含可连字字符时仅一次字符掩码预扫描（O(n) 位运算）；含可连字序列时每个候选子区间一次 horizontalAdvance 调用。
- 校验结果不做跨帧缓存（字体切换后自动失效，规避缓存一致性问题）；如 benchmark 显示开销 >10% 再考虑引入按字体+字符串的小缓存。
- benchmark 新增连字场景列：开启后重绘耗时增量 <10% 为通过。

### 3.7 字体回退行为

字体无连字字形（如 DejaVu Sans Mono）时，整形输出即逐字字形序列，宽度校验通过，整段绘制结果与逐格绘制**视觉一致**——静默回退，无需特判。

## 4. 测试设计

全部基于轮 5/6 现成离屏像素等价框架（offscreen QImage 渲染 + 逐像素比较）：

1. **连字生效**：构造 `->`、`!=`、`==>` 序列，连字字体（CI/本机需有 Fira Code 或等价；缺失时该用例 QSKIP）下开关开启渲染结果与关闭时**不同**（连字字形替代逐字字形），且序列外区域逐像素一致。
2. **静默回退**：无连字字体下开/关渲染逐像素一致。
3. **脏区扩展**：写入连字序列后修改其中间一格，断言重绘区域覆盖整个序列（内部观测点惯例，镜像 `_drawTextTestFlag`）。
4. **样式边界**：`->` 两字符 rendition 不同（分属两个片段）时不连字，各自独立绘制。
5. **互斥**：bidi 开启 / #33 修复开启时连字不生效（渲染与开关关闭一致）。
6. **benchmark**：连字场景列，开启增量 <10%。

## 5. 风险与回退

- 风险：整形宽度校验在边缘字体（非严格等宽）下误判 → 结果只是"整段绘制"，与现状 drawText 整段行为相同，不产生新故障模式。
- 风险：脏区扩展遗漏导致连字墨迹残留 → 保守整行升级兜底，正确性优先。
- 回退：开关默认关闭即完整回退；代码上连字路径全部收在 `if (_ligaturesEnabled)` 分支内。

## 6. 成功标准

- ctest 9 套件全绿 + 新增用例全绿。
- 连字字体下 `->` 等序列渲染为连字字形（像素差异证明），非连字区零差异。
- 开关关闭时与现状逐像素一致（像素等价双路径门禁）。
- benchmark 连字场景开启增量 <10%。

## 7. 修订记录（2026-08-14，用户裁定）

任务 4 benchmark 实测：条带裁剪重绘机制（§3.3 拆分绘制）开启增量 614%
（0.63ms → 4.5ms），远超 §3.6 的 10% 门禁且无可接受的优化空间（整形开销
O(片段长 × 条带数) 为机制固有）。用户裁定整改方向为**真实开关语义**，
本规格以下章节随之作废或修订（原章节正文保留作决策历史）：

- **§3.3 拆分绘制作废**：`drawLigatureSpans` 条带重绘机制与
  `ligatureSplitFragmentCount()` 观测钩子删除。新语义：**关 = 在绘制字体上
  `QFont::setFeature(QFont::Tag("liga"), 0)` / `("calt", 0)` 显式禁用连字
  特性（Qt ≥ 6.7；Qt < 6.7 无此 API，关侧退化为现状行为，代码内注释声明）；
  开 = 不设任何特性，沿用字体默认整形**（HarfBuzz 默认启用 liga/calt，等宽
  连字字体自然产出连字字形）。绘制调用本身开/关统一为单次整段 drawText，
  两侧开销相等（实测增量 ≈0%，见下）。特性差异并入 drawCharacters 既有字体
  调整块的 setFont 触发条件（`isFeatureSet` 判定），常态不引入无谓 setFont。
- **§3.4 三开关互斥作废**：bidi 不再与连字互斥（bidi 路径同为单次整段绘制，
  开时同样产出连字，tst_rendering 用例实测验证）。quardCRT #33 修复开关也
  不抑制连字：等宽字体（_fixedFont）下字体度量宽 ≠ 格宽的字符在 drawContents
  片段聚合时被 smallWidth/bigWidth 条件隔离为单字符片段，#33 逐字路径结构性
  只作用于孤立字符片段，连字序列恒走整段路径（整改中实测确认：试图构造
  "同一片段内宽度不一致字符 + 连字序列"触发逐字路径覆盖连字的用例不可行，
  逐字路径本身整形上下文为单字符、无连字，但该路径永不见连字序列）。
- **§4.1 开≠关主路径变为真实可达**：关侧特性禁用后，连字字体下开/关渲染
  必然不同（断形基线分支保留作开侧未出连字异常字体的兜底）。
- **性能实测（本机，Release，Qt 6.11.1）**：testLigatureRefresh 关 0.47ms /
  开 0.46ms（增量 ≈ -2%，测量噪声内），满足 §3.6 门禁。
- **保留不动**：LigatureHelper（候选字符掩码 / 子区间探测 / 宽度校验）与
  §3.5 跨度脏区扩展（仍由 `_ligaturesEnabled` 门控，新语义下关开关即无连字
  渲染，门控天然正确）；tst_ligature 套件不动。
